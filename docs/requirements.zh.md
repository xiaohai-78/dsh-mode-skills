# 需求

Skill 管理必须做到什么，以及每一部分是怎么验证的。需求只在这里写一份：一个功能在 `.scratch/<功能>/` 下的需求稿，做完后并进这里。用词以 [GLOSSARY.zh.md](../GLOSSARY.zh.md) 为准；设计背后的理由见 [docs/adr/](adr/)。

## 给谁用

用 DSH、有好几个 Agent 模式、Skill 也不止几个的人。DSH 会把找到的每个 Skill 放进每个带 Skill 工具的模式。想在某个模式里关掉一个 Skill、看每个模式加载了什么和要花多少 token、或者安装别人发布的 Skill，都得手动改配置和文件夹。

## 目标

- 在侧栏有一个页面，管理电脑上的每个 Skill。
- 按模式开关每个 Skill，中间还有「仅手动」和「仅模型」。
- 不离开 DSH 就能新建、编辑、导入、安装、保存版本和删除 Skill。
- 决定 Skill 的使用范围：仅 DSH，或所有 Agent。

## 不做的事

- 不从 GitHub 以外的平台安装，比如 GitLab、Gitee。
- 不装私有仓库。
- 项目里的 Skill 不提供「所有 Agent」。
- 不永久删除其他 Agent 工具目录里的东西：只删本插件建的链接，内容相同的副本移进回收站。

## 约束

- 单独安装就能按模式管理 Skill。
- 和 dsh-modes 一起装时只有一份数据：按模式的设置、新建、导入和版本都通过 dsh-modes 保存（[ADR 0002](adr/0002-mode-manager-owns-shared-data.zh.md)）。
- 卸载后模式照常能用（[ADR 0003](adr/0003-policy-row-switches-off-after-uninstall.zh.md)）。
- 入口在侧栏「插件」下面。
- 页面跟随 DSH 的语言，所有文字都有中英文。
- 页面里能检查新版本并升级插件。
- 页面绘制出错时显示错误原文和「重新加载」，不会是一片空白。
- 支持 Windows、macOS、Linux，Node `^22.19.0 || >=24`。
- README 和市场介绍只写验证过的事。

## 功能

### 按模式开关

**验收标准**

- 每个 Skill 在每个加载 Skill 的模式里都能设成「开」「仅手动」「仅模型」或「关」，也能一次在所有模式里打开或关闭。
- 「仅手动」让模型看不到它，但 `/名字` 还能用；「仅模型」让模型能用，但 `/` 菜单里不出现。
- 不加载 Skill 的模式，以及模式里没有的 Skill，不能设置，并说明原因。
- 「列表全部打开」和「列表全部关闭」作用于当前显示的列表，并提供撤销。
- 模式里已经有本插件的那一行时，改动从下一步起对正在运行的会话生效；一个模式里的第一次改动对新会话生效，提示里写明是哪个模式。

**验证记录**

- 只装本插件时，在标准模式关掉一个 Skill，模式里加上了带条件的策略行，列表显示该模式「已关闭」；页面上用开关关掉、再打开都正确保存，提示文字符合上面的生效时机。
- 把一个 Skill 在标准模式设成「仅手动」后，标准模式的目录少了这一项，标准模式会话的 `/` 菜单里它仍在、并标为 user-only。把一个 Skill 设成「仅模型」后，注册表自己的列表里该模式显示「仅模型调用」。对一个模式「列表全部关闭」后撤销，所有设置恢复。
- 模型实际看到的（模拟模型收到的请求）：标准模式里一个 Skill 是「仅手动」、一个是「关」、一个是「仅模型」，目录里有「仅模型」的那个，另外两个没有；PTC 模式里都是「开」，`/weekly-report` 注入了这个 Skill 的内容；在标准模式（它是「仅模型」）里同样的一行只是普通文字。
- 还没验证：*正在运行*的会话何时拿到改动后的 Skill 目录；这一点和 dsh-modes 用的是同一种机制（提供方失效和文件监视）。

### 和模式管理一起用

**验收标准**

- 装了 dsh-modes 时，按模式的设置、新建、导入和版本都通过它保存，两个页面显示同一份数据。
- dsh-modes 没有的「仅手动」「仅模型」这时不能用，并说明原因。
- 装 dsh-modes 之前本插件保存的「关闭」设置，可以交给 dsh-modes。

**验证记录**

- 页面显示由模式管理负责；在这里关掉 PTC 模式的一个 Skill，设置写进了 dsh-modes 的 `skills.json`，本插件自己的设置没有变化。
- 页面上的新建、读文件、保存版本、导入列表和导入都发给了 `/api/dsh-modes`；Skill 信息、版本和导入记录写进了 dsh-modes 的数据，本插件自己的数据里没有。
- 「仅手动」不可选并写明原因，其余照常可用。
- 「交给模式管理」把一项「关闭」写进了模式管理的设置，并在这里清掉了。

### 卸载后模式照常能用

**验收标准**

- 插件删除后，它改过的每个模式都还能加载、能开会话。
- 重新安装后，原来的设置恢复。

**验证记录**

- `dsh plugin remove` 并删掉插件文件后，标准模式仍在模式列表里，能新建会话；重新安装后，关掉的 Skill 又是关闭状态。

### 查看和整理 Skill

**验收标准**

- 列表显示各模式能看到的每个 Skill，带来源、说明和它在每个模式里的状态。
- 搜索匹配名称、说明、显示名、标签和 Skill 文件的正文。
- 显示名和标签只保存在本插件的设置里，从不写进 Skill 文件。
- 选了项目文件夹时，加上这个项目的 Skill。
- 每个 Skill 和每个模式的目录都显示估算的 token 开销，列表可以按它排序。

**验证记录**

- 各模式的 Skill 目录开销显示正确，按 token 排序有效。
- 显示名和标签保存后显示在行上；只出现在正文里的词能搜到对应的 Skill；填上项目文件夹后列出了该项目的 Skill（带来源和 token 开销）。

### 新建、编辑、版本和回收站

**验收标准**

- 新建的 Skill 直接打开编辑器，只在为它选的模式里开启。
- 编辑 SKILL.md 或其他文件时先保存当前文件；编辑期间文件被别处改过，会提示。
- 没保存的修改在折叠这一行或去别的页面后仍在。
- 版本可以带备注保存、查看、恢复和删除。
- 删除的 Skill 进回收站，可以恢复或彻底删除，提示里有撤销。
- 属于已安装包的 Skill 不能修改。

**验证记录**

- 新建的 Skill 直接打开编辑器，只在选中的模式开启；编辑保存前存了版本；保存（带备注）、查看、恢复、删除版本都正确。
- 在 Skill 文件夹里新建的文件保存后出现在列表里。
- 删除、撤销、从回收站恢复都正确。

### 从其他工具和文件夹导入

**验收标准**

- 能导入 Codex、Claude Code（包括插件里的 Skill）、其他 Agent 工具的 `~/.<工具>/skills`、任意文件夹，以及上传的 `.zip` 或文件夹里的 Skill。
- 重名时可以改名导入，或者在保存版本后覆盖现有的 Skill。
- 其他工具里指向 DSH 已有 Skill 的链接，标为「已是 DSH 的 Skill」。
- 导入的 Skill 来源后来变了，会标出「来源有更新」，可以重新导入。

**验证记录**

- 从 Codex 和 Claude Code 导入了两个 Skill，同名的没有预选；改动 Codex 里的来源后列表标出「来源有更新」，重新导入后提示消失并留下导入前的版本。
- 能列出 `~/.cursor/skills`，上传 zip 后导入成功。
- 导入列表把 Claude Code、Cursor、Gemini CLI 里的链接标为「已是 DSH 的 Skill」。

### 从 GitHub 安装

**验收标准**

- 仓库地址、仓库里的分支和文件夹、指向 SKILL.md 或它原始文件的链接、git 地址、skills.sh 页面，或 `skills add` 命令，都能列出这个公开仓库里的 Skill。
- 只有地址点名的那个 Skill 会被选中；含脚本的 Skill 会标出来。
- 其他网站的地址会被拒绝，并说明是哪个网站。
- 「检查更新」找出文件夹在仓库里变了的已安装 Skill，「全部更新」先把当前文件存成版本再覆盖。

**验证记录**

- 读取了真实仓库（`anthropics/skills`），从里面安装了三个 Skill，把其中一个伪造成旧版本后「检查更新」发现了它，「全部更新」覆盖成功。

### Skill 商城

**验收标准**

- 商城搜索 skills.sh，并列出插件自带的推荐仓库。
- 打开一个结果会读取它的仓库并选中那个 Skill；用户确认之前什么都不安装。
- 搜索框为空、或框里的文字全被选中时粘贴链接，会直接打开那个仓库；手动输入的链接按回车或点「打开」。
- skills.sh 列出的 Skill 仓库里已经没有时，页面会说明。

**验证记录**

- 搜索 skills.sh 并打开一个结果，读取了它的仓库并且只选中了那个 Skill；推荐列表正常显示。
- 在商城搜索框里分别粘贴 `https://skills.sh/anthropics/skills/pdf`、`npx skills add https://github.com/anthropics/skills --skill docx` 和指向某个 Skill 文件夹的 `tree` 链接，都读取了 `anthropics/skills` 并只选中了那一个；输入 `anthropics/skills` 按回车列出了全部 20 个、一个都没选；GitLab 地址被拒绝，并说明了网站。

### 各模式的使用统计

**验收标准**

- 「使用统计」按模式统计每个 Skill 在 7、30、90 或 365 天里被加载的次数，分模型调用和 `/名字`，并显示最近一次的时间。
- 列出没人用过的 Skill，可以在某个模式里关掉它们，并提供撤销。
- 只从会话记录里读名称和时间，从不读消息内容。

**验证记录**

- 用本地模拟模型，一个会话（标准模式）用 `skill` 工具加载了一个 Skill，另一个会话（PTC 模式）输入了 `/weekly-report`：「使用统计」从真实的会话日志里各数了一次，并算在各自的模式下。

### DSH 没加载的 Skill

**验收标准**

- 有 SKILL.md 但 DSH 没加载的文件会列出来，并写明原因。
- 能机械修复的，给出修复后的内容供查看和保存，保存前先备份旧文件。

**验证记录**

- 一个 description 含冒号的 SKILL.md 被列为没被加载，保存给出的修复后 DSH 加载了它。

### 使用范围：仅 DSH 或所有 Agent

**验收标准**

- 用户自己目录里的每个 Skill，在行上显示使用范围，展开后可以切换。
- 「所有 Agent」在共享目录里只保留一份，并链接到其他每个已安装的 Agent 工具（[ADR 0001](adr/0001-all-agents-is-one-copy-and-links.zh.md)）；「仅 DSH」把它移回 `~/.dsh/skills` 并删掉这些链接。
- 切换之前，页面说明会对每个工具做什么；工具里不同内容的同名 Skill 不会动，内容相同的副本换成链接，原来那份放进回收站。
- 「其他 Agent」列出找到的工具，补上缺的链接，并能把所有仅 DSH 的 Skill 一次给所有 Agent 用。
- 新建或导入时选「所有 Agent」会立即链接；删除时删掉链接，恢复时再补回来。

**验证记录**

- 在一个有 Claude Code、Codex、Cursor、Gemini CLI 目录、装了 dsh-modes 的环境里，对一个 Skill 选「所有 Agent」，它被移到 `~/.agents/skills`，Claude Code 和 Cursor 的目录里各多了一个相对链接，Gemini CLI 里内容不同的同名 Skill 没被动，和确认框说的一致。
- 「其他 Agent」列出了四个工具和各自的数量，把剩下的仅 DSH 的 Skill 一次给了所有 Agent，Cursor 里内容相同的副本换成了链接，原来那份进了回收站。
- 「仅 DSH」把 Skill 移了回来并删掉了链接；新建时选「所有 Agent」的 Skill 立刻链接好了。

### 插件自身的更新

**验收标准**

- 有新版本时页面会提示，用户确认后通过 DSH 的插件管理器安装（[ADR 0006](adr/0006-plugin-updates-itself-through-dsh-plugin-manager.zh.md)）。
- 自动检查可以关掉；本地开发安装从不检查。
- 升级之后，新版本会说明它已经在运行。

**验证记录**

- 对着真实的 npm 源，标成 0.1.9 的副本发现了 0.2.0，「升级…」通过 DSH 的安装器装上了它，配置随后依赖 0.2.0 的压缩包；在 0.2.1-rc.2 上新版本不用重启就换上了。
- 再装一次同一个版本，会提示已经装好、重启后生效。
- 手动写入的升级记录在页面上显示为「已升级到」，点「关闭」后记录被清掉。

### 页面出错时

**验收标准**

- 页面绘制时出错，显示错误原文和「重新加载」按钮，点了重新加载页面。
